# Booked ≠ Billed

**A job-outcome ledger for AI voice agents in the trades.**

An unsolicited product teardown + working prototype, built for [Sameday](https://sameday.ai) (YC W23).

---

## The thesis in one paragraph

Sameday's dashboard answers *"did the AI handle the call?"* The contractor's P&L answers *"did that call turn into money?"* Those are different questions, and today nobody closes the gap between them. A call can be answered in four seconds, booked with a clean transcript, scored 9/10 by QA — and still end in a cancelled appointment, a truck sent for the wrong trade, or a tech standing on a porch nobody answers. The AI's scoreboard says win. The contractor's week says otherwise.

That gap is where renewals die. Not because the AI performed badly, but because **the vendor and the customer are grading different exams.**

## Why this matters commercially, not just philosophically

Sameday sells at $449–$789/month against a metered-minute meter. A contractor deciding whether to renew that line item does one of two things:

1. Looks at a dashboard of calls answered and booking rates → *"seems fine, I guess?"* → churns the first slow month.
2. Looks at a number that says **"Sameday booked $82,000 of work we'd otherwise have missed, at a cost of $2,700"** → renews without a meeting.

Only one of those is a defensible renewal, and it requires reading data back *out* of ServiceTitan / Housecall Pro / Jobber / FieldRoutes — not just writing appointments *into* it. That read-back loop is the product this repo argues for.

It also happens to be the thing the competitive set doesn't do. The category has converged on the same three modules — book, win back, coach — all of which measure the conversation. Nobody measures the job.

## Run it

```
python3 make_data.py    # optional - regenerates synthetic inputs (already committed)
python3 ledger.py       # writes report.html
open report.html
```

No dependencies, Python 3.9+, about 200 lines. It reads two CSVs — an AI call log and an FSM job export — joins them on appointment ID, and renders a one-page report showing the **call to booked to dispatched to completed to invoiced** funnel, attributed revenue against platform cost, and a leakage table ranking the reasons booked work never billed.

### Sample output

Running against the synthetic quarter (812 AI-handled calls at one mid-size multi-trade contractor):

```
812 AI calls -> 373 booked -> 306 dispatched -> 256 completed -> 238 invoiced

booked-to-billed             64%
booked value never billed    $106,342
incremental revenue          $82,067    (after-hours calls only)
return on platform cost      30x
```

The leakage table is the interesting output. In the sample data the biggest dollar losses aren't calls the AI *lost* — they're calls it *won badly*. The top row is **capacity conflict: booked into a slot the business couldn't actually serve**, ahead of ordinary customer cancellations. Every one of those is a call a conversation-level dashboard scored as a success.

That's the whole argument, in one table.

## On attribution

The headline revenue figure credits the AI only for calls that arrived after hours or at weekends — calls that would otherwise have hit voicemail. Gross attribution across all AI-handled calls is roughly 2.3x larger and is shown in the report for completeness, but it's the number a contractor will argue with, and losing that argument costs more than the bigger figure wins. A ledger that gets disputed once is a ledger nobody opens again.

## Data disclaimer

**Every row in `data/` is synthetic and generated by `make_data.py`.** I have no access to Sameday systems, customers, or call data, and nothing here is a claim about Sameday's real performance. The numbers exist to make the prototype run and the argument concrete. If the shape is wrong, that's the useful part of the conversation.

## Where I'd be wrong

Worth saying out loud, because a teardown from outside the building usually is:

- **This may already exist.** If the read-back loop is built and I just can't see it from the outside, the finding isn't "build this," it's "your highest-value capability is invisible to buyers" — still a product problem, just a different one.
- **FSM write-back permissions are the hard part.** API access tiers, per-customer OAuth scopes, and the number of smaller contractors running their books somewhere no API reaches could make this a top-of-market feature only. That changes the sequencing, not the thesis.
- **Attribution will be argued with.** A contractor whose office manager rescheduled an AI-booked job will contest the credit. The ledger has to be conservative and legible enough to survive that conversation — a constraint I've only partly addressed here.
